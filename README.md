# 📁 Documents — Smart Personal Task Manager (SPTM)

This branch contains the **official project documentation** for the **Smart Personal Task Manager (SPTM)**, developed as part of the **CSE443 – Object Oriented Analysis and Design** course.

All written and visual artifacts that define, design, and justify the system architecture are maintained here.

---

## 📌 Included Documents

| Document                                 | Description                                                                                                                                                                                                      |
| ---------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Requirements Analysis Document (RAD)** | Defines system purpose, scope, stakeholders, functional and non-functional requirements, use cases, scenarios, system models, UI mock-ups, and requirement traceability.                                         |
| **Software Design Document (SDD)**       | Describes the complete architectural and detailed design of the system including subsystem decomposition, design patterns, deployment architecture, data management, security, and traceability to requirements. |

**Currently available:**

* ✅ *CSE443 – RAD_TeamSeaways (v1.0)*
* ✅ *CSE443 – SDD_TeamSeaways (v1.0, Dec 2025)*

---

## 📝 Purpose of This Branch

This branch is the **single source of truth** for all documentation related to the Smart Personal Task Manager. It is intended to support:

* 📘 Instructor and TA reviews
* 👥 Team collaboration and alignment
* 🧠 Design validation before implementation
* 🧪 Testing and verification activities
* 📦 Final project submission

---

## 📌 Documentation & Branching Policy

* 📄 **All documentation updates must be committed to the `documents` branch**
* 🔄 Do **not** merge documentation files directly into `main` or `development`
* 🔗 Other branches may reference the finalized documents when required
* ✅ Only reviewed and finalized documents should be considered official
